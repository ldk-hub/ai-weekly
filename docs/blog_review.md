## 🛑 프롤로그: "아, 또 새로운 모델이 나왔어?"

매일 아침 눈을 뜨면 새로운 AI 논문이 쏟아지고, 퇴근할 때쯤이면 어제 배운 프롬프트 기법이 구식이 되어버리는 시대입니다. 
Hacker News, GeekNews, Reddit, X(Twitter), Threads... 정보의 출처는 넘쳐나는데, 정작 내 업무와 성장에 '진짜 필요한' 엑기스만 걸러내기란 쉽지 않죠. 결국 즐겨찾기만 잔뜩 쌓아두고 "나중에 읽어야지" 하며 스크롤만 넘기다 지쳐버린 경험, 다들 있으실 겁니다.

**"매일 쏟아지는 AI 뉴스와 도구들을 피로도 없이 한 곳에서 볼 수는 없을까?"**

이런 고민에서 출발하여, 저격형 맞춤 큐레이션 플랫폼 **[AI위클리 (AI Weekly)](https://ldk-hub.github.io/ai-weekly/)**를 기획하고 개발하게 되었습니다.

## 🚀 AI위클리, 무엇이 특별한가요?

AI위클리는 사람의 개입 없이 **100% 자동화된 AI 에이전트(Claude Code)**가 굴러가며 만들어내는 '종합 AI 기술 동향 대시보드'입니다. 

사용자가 사이트에 접속했을 때 가장 핵심적인 정보만 직관적으로 얻어갈 수 있도록 크게 **3가지 섹션(3대장)**으로 구성했습니다.

### 1. 📰 데일리뉴스: "출근길 3분 컷! 매일 아침 AI 3줄 요약"
여기저기 흩어진 매체들의 뉴스를 돌아다닐 필요가 없습니다. 
AI위클리는 매일 아침 글로벌 주요 커뮤니티의 피드를 싹 긁어모은 뒤, **Gemini API**를 활용해 가장 주목받는 핫이슈를 선별합니다. 
길고 복잡한 기사도 바쁜 현대인을 위해 **직관적인 3줄 요약**으로 제공되므로, 커피 한 잔 마시며 가볍게 트렌드를 캐치할 수 있습니다.

### 2. 🧩 인기 플러그인: "이번 주 뜨는 Claude Code 도구들"
요즘 개발자들 사이에서 핫한 'Claude Code' 생태계. 수많은 플러그인과 도구들이 쏟아지지만 정작 쓸만한 걸 찾기는 모래사장에서 바늘 찾기입니다.
AI위클리는 매주 월요일마다 GitHub 트렌딩과 커뮤니티 반응을 종합하여 **'이번 주 핫하게 뜨는 도구(Rising)'**와 **'이미 검증된 필수 레퍼런스(Classic)'**를 딱 정리해서 보여줍니다.

### 3. 📈 스타보드: "어떤 오픈소스가 진짜 대세일까?"
단순히 새로 나온 도구를 소개하는 것에 그치지 않고, 오픈소스 생태계에서 실질적으로 검증되는 프로젝트들의 성장 궤적을 투명하게 보여주기 위해 **스타보드(Starboard)** 리더보드를 신설했습니다.
누적 스타 수에 따라 Minor, Major, Premier, Legend 등 체급별 리그를 나누고, 매주 월요일마다 이전 주 대비 스타 증감률(Velocity)을 추적하여 생태계의 진짜 흐름을 가시적으로 보여줍니다.

## 🤖 비하인드 썰: 이 모든 게 100% 자동화라고?

AI위클리의 가장 큰 매력은 겉으로 보이는 심플한 UI 뒤에 숨겨진 **무시무시한 자동화 파이프라인**입니다.

이 사이트에는 별도의 무거운 백엔드 서버나 DB가 없습니다. 순수 HTML과 JS, 그리고 JSON 파일로만 굴러가는 가벼운 정적 사이트(SPA)입니다.
그렇다면 데이터는 누가 채울까요?

- **안티봇 우회 수집**: Playwright와 로컬 세션 연동 기술을 사용해, 봇 접근을 빡빡하게 막는 소셜 미디어 피드까지 무손실로 긁어옵니다.
- **5중 서브에이전트 릴레이**: 인기 플러그인을 선정할 때는 무려 5명의 Claude Code 서브에이전트가 각자의 역할을 맡아(스캔 -> 검증 -> 분류 -> 요약 -> 배포) 파이프라인을 돌립니다.
- **AI 큐레이터**: 수집된 원시 데이터(Raw Data)는 Gemini와 Claude 모델을 거쳐 아름다운 한국어 3줄 요약과 해시태그로 정제됩니다.

사람은 그저 주 1회, 일 1회 트리거만 걸어두면 **나만의 똑똑한 AI 비서들이 알아서 뉴스를 읽고, 정리하고, 웹사이트에 퍼블리싱**까지 끝내버리는 것이죠.

## ✨ 번외: 미친 디테일의 모바일 UX와 Clean URL

AI위클리는 단순히 백엔드 자동화에만 집착하지 않았습니다. 독자들이 매일 방문하는 공간인 만큼, **앱(App) 수준의 네이티브한 사용성**을 제공하기 위해 프론트엔드 대공사를 진행했습니다.

- **완벽한 반응형 뷰포트**: 380px, 480px, 640px, 768px 등 기기 해상도별로 촘촘하게 미디어 쿼리를 나누어, 가로 오버플로우나 레이아웃 깨짐을 원천 차단했습니다.
- **터치 타깃 최적화**: 모바일 사용자를 위해 모든 버튼과 네비게이션 요소의 터치 영역을 최소 44px 이상으로 확보하여, 출퇴근길 지하철에서도 오터치 없이 쾌적하게 조작할 수 있습니다.
- **Clean URL (확장자 숨김)**: 기존 `news.html` 처럼 투박하게 노출되던 주소를 GitHub Pages의 기능을 활용하여 `.../news` 처럼 깔끔하게 떨어지도록 매만졌습니다. 세세한 주소창 디테일도 놓치지 않았죠.
