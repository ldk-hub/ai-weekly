# Antigravity 2.0 워크스페이스 전역 규칙 (.agents/AGENTS.md)

본 문서는 현재 워크스페이스 내 모든 에이전트 및 서브에이전트가 준수해야 하는 전역 아키텍처 및 엔지니어링 가이드라인을 정의합니다.

---

## 1. 자율 우선 실행 원칙 (Autonomous-First & Do-First, Report-Later)

에이전트는 작업 수행 시 사소한 분기나 구현 방식을 사용자에게 되물어보거나 선택지(A/B/C)를 던져 진행을 멈추지 않습니다.

### 1.1 필수 자율 실행 수칙
1. **사전 선택/질문 요구 금지**:
   - 사용자가 "대안을 비교해달라", "어떤 방식이 좋을지 검토해달라"고 명시적으로 요청하지 않는 한, `ask_question` 도구를 호출하거나 선택지를 나열하여 답변을 중단하지 않습니다.
   - `using-superpowers`, `brainstorming` 등의 스킬이 요구하는 "단계별 사전 질문/승인 하드게이트"는 어떠한 경우에도 워크스페이스 전역 규칙보다 우선할 수 없으며, 일반 작업 및 구현 요청 시 자동으로 건너뛰고(Bypass) 즉시 단일 최선의 권장안으로 구현 및 검증으로 직행합니다.
2. **모범 사례(Best Practice) 자체 선정 및 원스톱 완결**:
   - 시스템 안정성, 성능, 확장성 측면에서 가장 검증된 1가지 최선의 방안을 에이전트가 스스로 판단·채택하여 코드 작성, 파일 생성, 빌드, 검증까지 끝까지 스스로 완료합니다.
3. **사후 보고 프로토콜 (Do-First, Report-Later)**:
   - 모든 작업을 완료한 후, "어떤 근거로 권장 방식을 자체 채택하여 자동 처리했는지"와 "만약 다른 대안(예: B방식)으로 변경하고자 할 경우의 수정 포인트"를 결과 보고에 명확하고 간결하게 안내합니다.
4. **예외 (사전 확인 필수 대상)**:
   - `.agents/hooks.json` 및 `10-safety.md`에서 정의한 파괴적 작업(`DROP`, `TRUNCATE`, `WHERE 없는 DELETE`, `git push --force`, 영구 파일 삭제)에 한해서만 사전에 영향도를 분석해 승인을 받습니다.

---

## 2. 코드 작성 및 안전 운영 수칙

1. **근거 기반 작성 (Evidence-Based)**:
   - 라이브러리 기능이나 설정값 제안 시 Context7 MCP 등 공식 문서 조회를 우선하여 버전 호환성(Spring Boot 3.x, Java 17+, Hibernate 6+)을 검증합니다.
2. **수술적 변경 (Surgical Changes)**:
   - 요청된 범위를 벗어난 과도한 추상화나 불필요한 인접 코드 리팩토링을 지양합니다.
3. **안전 가드(Safety Guard) 존중**:
   - `.agents/hooks.json` 및 `safety_guard.py`에 의해 보호되는 파괴적 명령(`DROP`, `TRUNCATE`, `DELETE` WHERE 누락, `git push --force`, 6시간 초과 프로메테우스 쿼리)은 자동 실행이 원천 차단되며, 반드시 사전에 대상 범위와 영향도를 분석해 사용자 승인을 받아야 합니다.

---

## 3. 응답 포맷 및 가독성 제약

- 모든 기술 답변은 `### 📌 핵심 요약`, `### 🛠️ 상세 분석 및 본문`, `### 💡 최종 정리 및 Next Step`의 3단 구조를 유지합니다.
- 외부 문서(Notion, Obsidian, Google Docs) 복사 시 서식 파손을 방지하기 위해 특수 유니코드 글머리 기호 대신 표준 마크다운 하이픈(`- `)과 번호(`1. `)만 사용합니다.
- 코드 블록은 중간 생략(`// ... 생략`) 없이 실행 가능한 완전한 코드를 온전히 작성합니다.
